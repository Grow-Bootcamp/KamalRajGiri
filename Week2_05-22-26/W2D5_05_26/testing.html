Unit Testing

Unit testing is a software testing method that involves testing individual units or components of a program to ensure they function correctly. Usually they could be functions, methods, or classes or small modules.

Does this individual piece of logic behave correctly?
this doesnot involve database , real browser, frontend, External API etc so it is fast , focused , easier to debug, and good for business logic. It is usually done by developers and can be automated using testing frameworks like Jest, Mocha, or Jasmine for JavaScript, JUnit for Java, or PyTest for Python.

Integration Testing

A unit test might test the controller logic in isolation. But an integration testing may ask Do these components work correctly together?
here unit testing are done and those are kept together and tested as a group. It is usually done by developers or QA engineers and can be automated using testing frameworks like Selenium, Cypress, or TestCafe for web applications.

End-to-End Testing

E2E testing looks at the system from the user's perspective. It tests the entire application flow, from start to finish, to ensure that all components work together as expected. E2E tests simulate real user scenarios and interactions with the application, including frontend, backend, and external services. It is usually done by QA engineers and can be automated using testing frameworks like Cypress, Selenium, or Playwright.
Can the complete system perform the user's intended workflow?

Assertion

An assertion is a statement that says: "I expect this result to be true." In testing, assertions are used to verify that the actual output of a piece of code matches the expected output. If the assertion fails, it indicates that there is a bug or an issue in the code being tested. Assertions are commonly used in unit tests, integration tests, and end-to-end tests to validate the correctness of the code and ensure that it behaves as intended.
so conceptually: 

    Test
 │
 ├── Arrange → prepare data
 │
 ├── Act → execute function
 │
 └── Assert → verify result

There are several ways we can approach testing

  • Manual Testing : Developer does manual testing.
  • Automated Testing : Code automatically checks the appliation. eg npm test
  • Black-box Testing : We test the system without caring about its internal implemantation.we care about input => output
  • White-box Testing : We know the international implementation and test specific logic.
